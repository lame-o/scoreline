# Scoreline for the web: architecture

Scoreline for the web is the macOS app (`../Sources/Scoreline`) as a web app on Cloudflare Workers. The aim is complete parity with the Mac app, and the same bar: native-feeling, calm, precise, snappy, interruptible. This document is the contract for everyone building on it. ## Run it

Use pnpm (one store shared across worktrees) and Node 22.15 or later. Node 22.18 or later is better: `cf` loads `cloudflare.config.ts` with Node's type stripping, which older 22.x builds only have behind a flag. The package scripts pass that flag, so `pnpm build` works on both. A bare `cf build` needs Node 22.18 or later. `.nvmrc` says 24.

```sh
pnpm install
pnpm dev             # cf dev: Vite plus the Worker in workerd, on http://localhost:5173
pnpm build           # cf build: client assets and the Worker bundle (must pass)
pnpm preview         # build, then serve the built output locally
pnpm typecheck       # generates Worker types (cf workers types), then tsc -b over all four programs
pnpm test            # Vitest: parsers, scoreboard logic, settings, tokens' contrast
                     # (at background priority, `--maxWorkers=3`: the theaters' heavier tests otherwise pass 5 s)
pnpm test:e2e        # Playwright smoke and live-state tests against `pnpm dev`
pnpm fixtures [src]  # re-record trimmed fixtures from the live feeds (espn | bo3 | ifsc | teams | mlb | football | matches | profiles | college | odds | youtube)
```

Four TypeScript programs with different globals:

- `tsconfig.app.json`: the browser app (`src`, `shared`).
- `tsconfig.worker.json`: the Worker (`worker`, `shared`), with workerd's runtime types generated into `.cloudflare/types` by `pnpm types`.
- `tsconfig.node.json`: tooling and e2e.
- `tsconfig.test.json`: unit tests, which are app code plus Node.

All of them run in strict mode with `noUncheckedIndexedAccess`.

## The Worker and the upstream allowlist

The browser never calls a sports feed directly. It calls `/api/<host><path>?<query>`, and the Worker fetches the upstream, as long as it's on the allowlist in `shared/upstreams.ts`. Turning an upstream URL into its proxy path is mechanical, so a URL copied from the Swift sources works as is:

```ts
import { getJSON } from "../data/http";
const board = await getJSON("https://site.api.espn.com/apis/site/v2/sports/football/nfl/scoreboard");
// fetches /api/site.api.espn.com/apis/site/v2/sports/football/nfl/scoreboard
```

`proxyPath()` throws for anything off the list, so a missing entry fails loudly in development. These hosts and path prefixes are allowed:

| Host | Prefixes | Notes |
| --- | --- | --- |
| `site.api.espn.com` | `/apis/site/v2/sports/`, `/apis/v2/sports/` | scoreboards, summaries, teams, rankings, standings |
| `sports.core.api.espn.com` | `/v2/` | plays, probabilities, seasons, brackets |
| `site.web.api.espn.com` | `/apis/common/v3/` | athlete and team profiles |
| `api.bo3.gg` | `/api/v1/` | CS2, S-tier only (`CounterStrike.TIER`). It ignores `[gte]`/`[lte]` on `start_date` (every match since 2020 comes back): bound a window with `[gt]`/`[lt]` |
| `ifsc.results.info` | `/api/v1/` | the Worker adds the `Referer` the service requires |
| `statsapi.mlb.com` | `/api/` | Statcast |
| `gamma-api.polymarket.com` | `/events`, `/markets/slug/` | Direct (CORS `*`). Win Probability's odds: a league's day without its markets (`include_markets=false`), a game's moneyline by slug |
| `clob.polymarket.com` | `/prices-history`, `/midpoint` | Direct. A token's history, and the midpoint when the socket can't connect |
| `www.fotmob.com` | `/api/data/search/suggest`, `/api/data/teams` | soccer photos, injuries and the current coach (FotMob.swift): enrichment only |
| `www.youtube.com` | `/@WorldClimbing/live`, `/@WorldClimbing/streams`, exactly (`paths`) | World Climbing's stream on now or next, and its scheduled streams (ClimbingBroadcast.swift, ScheduleProvider `Streams`). Pages, not an API (about 1.3 MB each): asked in English (`Accept-Language: en-US`, the parsers read YouTube's English), with the proxy's own user agent and no cookies. A consent or bot page in their place reads as no answer, never as "nothing scheduled" |
| `decapi.me` | `/twitch/uptime/`, `/twitch/title/`, `/twitch/game/`, `/twitch/avatar/`, each then a Twitch login (`paths`) | a CS2 co-streamer's Twitch status and avatar as plain text, keyless (CoStream.swift); the owner approved it |

Nothing else is proxied. One WebSocket is allowed besides (`SOCKETS` in `shared/upstreams.ts`, and the CSP's `connect-src`): Polymarket's market channel, `wss://ws-subscriptions-clob.polymarket.com`. Images are never proxied: `<img>` loads logos and photos from their CDNs, sized by the CDN (`src/data/images.ts`: ESPN's combiner and bo3.gg's image proxy, which turns a 90 KB crest into 5 KB; `src/data/profiles/photos.ts` for people). FotMob's face crops load straight from `images.fotmob.com`, and a co-streamer's Twitch avatar from Twitch's CDN. An entry's `paths` (whole-path patterns) narrow its prefixes to exactly the pages it may ask for.

Each response is cached at the edge for as long as its kind of data stays true. Policies are matched by path, first match wins, and live at the top of `shared/upstreams.ts`:

| Policy | Edge | Browser | Used for |
| --- | --- | --- | --- |
| `LIVE` | 15s | 5s | scoreboards, summaries, plays, live rounds |
| `SHORT` | 60s | 15s | match lists, event pages, the fallback |
| `TABLES` | 10 min | 2 min | standings, polls |
| `SCHEDULE` | 30 min | 5 min | team schedules, seasons, profiles |
| `CATALOG` | 6 h | 1 h | team lists |

World Climbing's live page is a minute at the edge and 30 s in the browser (the Mac looks every 10 minutes, every minute around a start, every 2 while live); its streams tab half an hour and 5 minutes (ScheduleStore keeps it 30 minutes). decapi.me's status is `SHORT` (the Mac checks every 2 minutes), an avatar a day. Profile paths have their own rules: a team's page header (`/teams/:id`, with its record and next game), the NFL depth chart and transactions are `SCHEDULE`, not the team list's `CATALOG`; core athletes (`/athletes/:id`) and bo3.gg players are `SCHEDULE`; FotMob's search is a week at the edge (a club's ID never changes) and its squad twelve hours.

How the caching works (`worker/proxy.ts`):

- The Cache API holds each successful response under its upstream URL, stamped with the time it was fetched. On a hit, the response says how long the copy has left: `Age`, a browser `max-age` that never outlives the edge copy, and `CDN-Cache-Control` for Workers Caching.
- Workers Caching (`cache.enabled` in `cloudflare.config.ts`) sits in front. It collapses bursts of identical polls and works on `workers.dev`, where the Cache API is a no-op.
- Failures are never cached. Bodies stream through, and only `Content-Type` is copied from upstream.
- Every answer is data, never a page: a sandboxing `Content-Security-Policy` (`default-src 'none'; sandbox`) means an HTML upstream (World Climbing's YouTube pages) opened at its `/api` path can't run on this origin. `fetch` ignores it.
- Upstream fetches time out at 15 s: a timeout is a 504 (`upstream_timeout`), an unreachable upstream a 502. The Cache API is an optimization: a failing read falls through to the upstream and a failing write is logged, never failing the response.
- Only GET and HEAD are accepted. Unknown hosts, paths outside the prefixes and traversal attempts get a 404.
- Every miss and every upstream failure logs one structured JSON line.

The app's own pages and bundles are static assets, served before the Worker runs; `public/_headers` gives them their headers: a Content-Security-Policy the app runs under with no violations (scripts from the origin plus index.html's inline theme script by its hash, styles from the origin, data from `/api` only, images over https), `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, `Permissions-Policy` and COOP, and a year's immutable cache on the hashed `/assets/*`. Editing index.html's inline script means updating its hash in `_headers` (`test/unit/headers.test.ts` fails until you do).

URLs whose query changes on every call defeat the cache. The CS2 provider rounds its date window to the hour for this reason (see `listURL`). Do the same for any time-based query you add.

## Data layer

`src/data/` is pure TypeScript ported from the Swift sources: no React and no DOM (except `Intl` for formatting). Everything is testable in Node.

- `models.ts`: `Sport`, `League`, `ScoreEvent` (Swift's `Event`, renamed because `Event` is a DOM global), `Competitor`, `EventRef`, `GameClock`, and the live snapshots (`FootballSpot`, `BaseState`, `MatchMark`, `CSLive`, `WallState`). The data is plain, immutable and serializable: dates are epoch milliseconds and absent values are `null`.
- `leagues.ts`: the catalog, exactly as `League.catalog` (ids, names, short names, sources, order, defaults).
- `json.ts`: lenient readers (`at`, `str`, `int`, `arr`…). Every field is read on its own, so a schema change upstream drops one field, never the feed. This is the Swift `try? decodeIfPresent` habit. Never cast a response to a type.
- `providers/`: `espn.ts`, `counterStrike.ts`, `ifsc.ts`, `teams.ts`, behind `providers/index.ts` (`fetchLeagueEvents`). Each takes a `Fetcher`, so tests replay fixtures.
- `scoreboard.ts`: ScoreStore's pure logic:
  - filters: picks, college Top 25 and followed teams, climbing disciplines;
  - the visibility window: finals for 18 hours, games from 6 hours ago to 36 hours ahead, and the next fixture when that window is empty;
  - three per side of now;
  - My Teams;
  - live-first ordering;
  - the tile board and its plan;
  - poll cadence and retry delays;
  - what carries over between polls (`mergePoll`).
- `format.ts`: ordinals, plurals, `periodLabel`, days and times ("Today 7:00 PM", "Tomorrow", "Nov 5, 1:00 PM"), countdowns, "Updated 5 minutes ago", and `spokenStatus` and its siblings, which turn source shorthand into words for screen readers.
- Game pages: `gameDetail.ts` (GameDetail.swift: the detail model, ESPN's summary by ID, a game built from its summary, the baseball parsers; it hands bo3.gg matches and IFSC rounds to `cs2.ts` and `climbing.ts`), `cs2.ts` (CSDetail: the match, maps, tournament and stage, streams (official first; ### How to port a Swift parser

1. Find the Swift entry point (`Providers.swift`, `GameDetail.swift`, `ScheduleProvider.swift`…) and read it whole, including its comments. The comments explain the gotchas: ESPN's yard line counts from the home goal line, postponed games come back "post" with 0–0 placeholders, college needs `groups=80`, and so on.
2. Port the model into `models.ts`, or into a new `src/data/<area>.ts` if it only belongs to one page, with the same field names and doc comments.
3. Port the parser as a pure function `(json: JSONValue, …) => Model`, reading through `json.ts`. Keep the order of the Swift checks and its fallbacks. Keep the Swift comment beside the line it explains. Cite the Swift file in the module's header comment.
4. Put the fetching (the URLs, and parallel requests where one failure must not sink the rest, via `Promise.allSettled`) in a separate function that takes a `Fetcher`.
5. Record a small fixture (add it to `scripts/record-fixtures.mjs`, trim it to the fields you read), then write the tests. When the live state can't be recorded today, derive a `*.synthetic.json` from a recorded file and say how in its `_note`.
6. If the URL is new, add its host or prefix and cache policy to `shared/upstreams.ts`. Never touch the Worker for this.

## State: settings and live scores

Settings live in `src/state/settings.ts`: one typed, versioned store in `localStorage` (`scoreline.settings.v1`), synced across tabs. Read a slice with `useSettings((s) => s.followed)`, which re-renders only when that slice changes. Selectors must return stored values or primitives, never new objects. Change settings only through `settings.*` actions. The Mac's rules live there: a competition-scoped pick turns that competition's filter on; a global team follow applies across competitions without enabling them; an unfollowed competition keeps its scoped picks; a newly followed competition joins the end of the order.

| `odds` | true | `showOdds`. Settings → Live Games → Odds: Polymarket's live market and DraftKings' line in game pages' Win Probability. Off: ESPN's bar, and no Polymarket requests |
| `foldedModules` / `hiddenModules` | [] / [] | same: game-page modules folded and hidden, "<page>.<module>" ("nba.liveView", "soccer.pitch"), per sport, never per game (data/modules.ts) |
| `moduleOrder` | {} | same: each page kind's modules in the user's order, merged into each state's plan; only Customize's Restore Defaults removes it (`settings.setModules`) |

To add a setting:

1. Add it to `Settings` and `DEFAULTS`.
2. Read it defensively in `sanitize`.
3. Add an action if it has a rule.
4. Add a row to the table above.

A change of shape bumps the payload's `schemaVersion` and needs a migration in `sanitize`. Keep `scoreline.settings.v1` stable: the before-paint theme reader uses it. Version 2 preserves the effective all-games scope of legacy empty selections; intentional empty selections after migration show no games. The Mac-only settings (live count, open at login, updates) have no web equivalent; the menu bar's live score is the tab's (`scoreInTitle`).

**What's streaming** (`state/streams.ts`, ScoreStore's `climbingBroadcast`, `coStreamingIDs`, `coStreamerAvatar`): World Climbing's stream on now or next, the live CS2 matches the co-streamer is showing, and their avatar. The shell's watcher (`state/streamWatch.ts`, in LiveServices) keeps it as ScoreStore does: the live page only while climbing is shown and a competition is underway or within two days (10 minutes, a minute around a start, 2 while live; a failed look keeps what was known), the Twitch status every 2 minutes only while co-streams are on and a CS2 match is live, the avatar once. The match page's bo3.gg listing confirms a co-stream until the match ends (`streams.confirm`, ScoreStore.noteStreams). Rows, tiles and pages read slices (`useStreams`), so a change redraws only the marks it moves. The scores' climbing rows take the stream (`applyBroadcast` in `useScoreboard`): a live stream marks its round live, an upcoming one gives it its real start.

Per-tab state that isn't a setting: the pinned game (`state/pin.ts`, `pin.toggle(id)`, `useIsPinned(id)`), kept in `sessionStorage` (`scoreline.pinned`) as the Mac keeps its pin until quit.

Live scores live in `src/state/scores.ts`, where `useScoreboard()` makes one TanStack Query per required board (followed competitions, edition sources, followed teams' home boards, and their next fixture's actual catalog competition):

- Cadence, from ScoreStore: every 30s while anything you'd see is live, 60s before a start, otherwise 5 minutes.
- A failing league retries at 5s, 15s and 30s, then keeps its last good games, marked failed.
- Polling pauses while the tab is hidden, and refetches on return if the data is older than 30s. The exception is the shell's own reader (below).
- Offline, queries fail rather than pause (`networkMode: "always"`) and don't retry while the browser knows it's offline (`retryOnline`), so every page says it can't connect at once instead of holding its placeholders; reconnecting refetches. A league that has never answered counts as failed from its first failed try, and when every league has failed with nothing to show, the scores say "Can't Load Scores" once.

**Every other page's data** fails and recovers the same way, through `state/retry.ts` (ScoreStore's ladder, for every page): spread `...retrying()` (or `retrying({ every, failed })` for a query with its own cadence, or one whose answer can be a failure of its own, like the schedules' `ok: false`) into the query. Its first failure is the query's error at once (no retries inside a fetch), and it asks again at 5, 15, 30, then every 60 s while the page is open and the tab visible; offline, only on reconnect; a 404 never. Read it with `loadState(query)` (or `hasFailed(query)`): `failed` holds from the first failure through every attempt after it (TanStack puts a query without data back to "pending" while it asks again, which would flash the placeholders), `retrying` while an attempt is out, `stale` when a refresh failed under data still shown. A page shows `<ErrorState retriesAutomatically retrying={…}>` (the Mac's "Scoreline will try again automatically", and a quiet "Retrying…" held 1.2 s so a fast failure doesn't blink), or its data with a `StaleNote` / footer saying "Can't connect · Showing … from 10:42 AM". The schedule cache's own fetches don't retry (`cached` in state/schedule.ts): the page's query does, asking again only for what failed.

**What survives a reload** (`state/persist.ts`, ScheduleCache.swift, ProfileCache.swift): the schedule cache (boards, calendars, team schedules, bo3.gg's lists) and the team and player pages' responses are kept in IndexedDB through TanStack Query's fine-grained persister (`persisted({ family, version, maxAge })` as a query's `persister`). A reloaded page paints from its last copy at once and revalidates behind it when stale: an observed query refetches on restore; the schedule cache, which nothing observes, fetches a restored stale window itself and has the pages that read it re-read once it lands (`revalidate`), the Mac's ETag revalidation in effect. Each entry carries its family's version: profiles store raw responses (a fixed version); schedules store parsed values, versioned with their module's URL, which a build fingerprints with the parsers' code. Entries past their max age (profiles a week or their TTL, schedules twice their freshness, 2–30 days) are dropped when read, and each family sweeps its own at idle the first time a page uses it. Never persisted: scoreboards, a game's detail and lanes, standings, anything live. The persister is its own chunk, loaded with the first page that keeps data.
- Each poll is merged onto the last. Clocks learn whether they run. The NBA's routine plays don't replace the last line worth reading. An unchanged game keeps its object identity, so its row doesn't re-render.

- CS2: live matches with a followed team or pinned read bo3.gg's live snapshot (`data/providers/csLive.ts`, loaded only while a match is live): their rows say "Mirage 5–8", and in Tiles the first four live matches carry the round race.
- My Teams reaches into each followed team's schedule for its next game within 21 days when the scoreboards have none (`state/nextGames.ts`, `fallbackGames`); the pin orders the Live tier after your teams.

`useScoreboard()` returns the derived sections, the tile board, quiet leagues, the live count, status, `event(id)` and `leagueOf(id)`. A second reader beside one that already polls passes `{ poll: false }`, so the feeds aren't polled twice; the game page does this in the split view, where the sidebar polls. The shell's reader (app/LiveServices.tsx) passes `{ poll: "auto", background }`: it polls only when no page polls (Settings on a phone), and keeps polling a hidden tab while the tab's title or alerts need the news, at `backgroundInterval` (30s while a followed or pinned game is live, 60s before one starts, else 5 minutes). Results are recomputed only when a league's data changes, the settings change or the minute turns (ScoreStore's `version`). Game pages read their event from it, so they stay live.

`useNow(period)` (`state/clock.ts`) is the only way to tick. Every component on the same period ticks in the same frame, on the whole period, and tickers stop while the tab is hidden.

## Team and player pages

`src/features/profiles/` (TeamPage.swift, PlayerPage.swift and their sections), with the data in `src/data/profiles/` and `src/state/profiles.ts`.

**Routes.** One readable path per team and person, so a page can be shared and reloaded:

| Path | Who |
| --- | --- |
| `/team/espn-football-12` | a team, by its `Competitor.id` |
| `/team/espn-soccer-359?league=eng.1` | a club, with its domestic league (its roster needs it; without it the page asks ESPN) |
| `/team/cs-667` | a CS2 team |
| `/player/nba-1966`, `/player/mlb-39832`, `/player/college-football-…` | an ESPN athlete: league, then ID |
| `/player/eng.1-280555` | a footballer, under any soccer league |
| `/player/cs2-zywoo`, `/player/ifsc-1147` | a CS2 player by bo3.gg slug, a climber |

The pages also accept the paths built by hand before the links existed, so none of them 404: `/player/espn-<sport>-<id>?league=<league>` (the league's path, else the sport's: MLB, the NBA, the NFL, `soccer/all`), `/player/ifsc-<id>?name=&country=`, `/team/cs-<id>?name=&logo=&league=cs2` (the name and crest paint the hero at once), and a bare `/team/<id>` from a table row (a club finds its league from ESPN).

**Name links.** Any page can drop these in (`features/profiles/ProfileLinks.tsx`, a light module: no parsers, no page code):

```tsx
import { TeamLink, PlayerLink, teamRefFrom, espnPlayerRef, LinkOrigin } from "../profiles/ProfileLinks";

<TeamLink team={teamRefFrom(competitor, leagueID)}>{competitor.name}</TeamLink>
<PlayerLink player={espnPlayerRef("basketball/nba", athlete.id, athlete.name)}>{athlete.name}</PlayerLink>
<PlayerLink player={ref} variant="row" label="Jalen Brunson, number 11, 26.3 points">…a whole row…</PlayerLink>
<LinkOrigin name="Chiefs">…links on this page say "‹ Chiefs" on the page they open…</LinkOrigin>
```

- `variant="plain"` has no look of its own (the caller's class styles it, as the standings and poll rows and At the Plate's names do); `dataset={{ mine }}` sets `data-mine`, and `label` the accessible name.
- `variant="quiet"` (the default) is a name inside text: unchanged at rest, underlined under a fine pointer, dimmed while pressed (QuietLink). `variant="row"` is a row whose purpose is the thing it names: the list's hover fill, with `linkNameClass` on the name to underline it (RowLink). `rowLinkClass` gives the same look to rows that open something else (a game).
- `null`, or a team without a page (the WNBA), renders the children as plain text, so callers never branch. `counterStrikePlayerRef(slug, name)` and `climberRef(id, name)` build the other sources' references.
- A pointer resting 250ms prefetches the page's first request and the hero photo, and loads the page's chunk (at most six a minute, once per link, never with Save-Data or on 2G). Touch prefetches on press. Return on a focused link arrives with no entrance.
- **"Go to …"** (`features/profiles/GoToMenu.tsx`; ProfileLinks.swift `GoToPlayerItem`, `GoToTeamItem`, `PlayerPageLink`): a row whose click is taken (an NBA box score or leader line picks the player for the court; a climber's result or scorecard pins them) opens the person's page from its context menu (right-click, long press, Shift-F10 or the Menu key) or a double click: `const goTo = useGoToPlayer(ref)`, spread `goTo.props` on the row and render `goTo.menu` beside it (never inside: its clicks would reach the row). A right-click on the name, a link, keeps the browser's menu. A game row on a team or player page offers its opponent (`useGoToTeam(opponent, href)`) with Open in New Tab beside it. The team page's Results end in All Results, the team's schedule facing back.
- The link carries the full reference in the history state, so the hero paints the name, photo and team on the first frame; a shared URL loads the same page from the path.

**Data.** One TanStack query per upstream URL, keyed by the URL (`["profile", url]`), fresh for the Mac's TTLs (`TTL` in `state/profiles.ts`), kept on disk across visits (`state/persist.ts`): a dwell's prefetch, the page and Back share one copy, and each part fills in as it lands and fails on its own (the page shows the rest and a footnote with Try Again), retrying behind the page on the ladder (`state/retry.ts`). Raw responses are parsed once per response. `useTeamProfile(ref)` and `usePlayerProfile(ref, { careerRequested })` assemble the pages: the roster grouped per sport and filled from the leaders, the NFL depth chart (which also orders the roster), soccer squads with FotMob's photos, injuries and coach (after ESPN's, never blocking), the MLB other-role log kept only when it has a game with something in it (`hasPlay`), college tiles from the season line (kickers and punters by their own lines, a web addition), NBA and soccer ranks from the league leaders. College asks for its whole roster (`?limit=200`): ESPN pages it at 100 by surname, and every FBS roster is longer, so its first page lost a team's T-to-Z players (often a leading receiver, a tackler, the kicker) and Leaders with them. A game log's strip is chosen by the link's position, else the bio's once it lands (a page opened from its URL, or from a game page's names, knows none). Games open under the page's league (`profileGameLeague`, the Mac's `.espn(path:)`), so one off the scoreboards is asked of that league alone. A 404 is an answer ("Player Not Available"; career by season's "No career stats yet."), never retried. A team's Results and its table aren't the page's own reads: they're the schedules layer's season (`useTeamSeason`) and the standings layer's table (`useStandings`), shared with the results and standings pages.

**The hero photo.** `heroPhotoURL` asks for the hero's size from the first frame (ESPN's 260×190 crop from the athlete ID, bo3.gg's 240px proxy), never the list's 96×70 thumbnail stretched. `PlayerPhoto` shows the monogram until the photo lands, fades it in once, and draws a photo already decoded this session (`state/profilePhotos.ts`) on its first frame with no fade. While a photo is on screen it's never swapped for another crop (`nextHeroPhoto`).

**The docked bar** (`DockedBar.tsx`, DockedBarHost): as the hero scrolls under the sticky header it tucks (scaled 6% toward its top and faded, written straight to its style each frame), and a glass bar in the team's color docks 4pt below the header: photo, name, team · position, the lead stat. Progress is quantized to 1/64 (`dockStep`); only the host re-renders on a step, and the bar is a memoized element on a zero-height sticky row, so the page never re-renders while scrolling and its layout never changes. A click goes back to the top. Reduce Motion: opacity only.

**Layout.** One column, or two from 680pt of page (`useProfileLayout`, `SectionColumns`: MatchColumnsLayout's blocks of left and right sections, a spanning section closing a block). A football roster spans both columns, its groups two-up. Each block adds columns from its own width class. The team-color wash stays put behind the page as it scrolls (the Mac's page background) and takes the crest's colors as a change of light.

**Page session.** `usePageSession(key)` keeps the choices that survive Back: Roster | Depth Chart, All Games, Batting | Pitching, expanded groups, career.

## Design system

Read `src/design/tokens.css` first.

**Units.** `--pt` is one Mac point. The root font size is the Mac's 13pt body (81.25% of the browser default, so it respects the user's text size). On touch screens the root is 15px and the whole layout scales with it. Write every length in Mac points, so a Swift layout ports number for number: `padding: calc(7 * var(--pt)) calc(8 * var(--pt))`. Container queries can't use `--pt`: use `rem` there, where 1rem is 13pt.

**Color.** Every color is defined once with `light-dark()`. The theme is just `color-scheme`: the system's by default, or Settings → Appearance, which sets `data-theme` on `<html>`; index.html applies it before first paint. The tokens:

- **Ink:** `--label`, `--label-secondary`, `--label-tertiary` (glyphs only, never text), `--separator`.
- **Washes:** `--fill-hover`, `--fill-press`, `--fill-surface`, `--fill-skeleton`, `--stroke-hairline`.
- **System colors:** `--accent` and `--accent-text`, `--live` and `--live-text`, `--live-wash`, `--live-pill`, `--delayed-text`, `--star`.
- **Charts:** `--viz-*` (grid, reference, track, neutral). Neutrals are ink opacities; team colors are for marks only.
- **Materials:** `--glass-fill` (`-strong`, `-clear`, and `--glass-solid` for chrome that content dissolves under), `--glass-blur`, `--glass-edge`, `--glass-highlight`, `--shadow-glass`, `--shadow-control`.

Text tokens clear 4.5:1 on the page, the glass and a pressed row, in both themes; `test/unit/contrast.test.ts` reads tokens.css to check it. Increase Contrast (`prefers-contrast: more`) strengthens edges and secondary ink. Reduce Transparency turns glass solid.

**Type.** System fonts throughout: SF on Apple devices, the system face elsewhere. `--font-rounded` (SF Rounded where available) is for scores and countdowns. Sizes follow the Mac: `--text-body` 13, `--text-callout` 11.5, `--text-status` 11, `--text-caption` 10.5, `--text-small` 10, plus the score sizes. Numbers are tabular wherever they line up. Section titles are small caps drawn by CSS (`text-transform`, `--tracking-caps`), so screen readers read them as written.

**Glass** is only for the floating layer: the sidebar, header controls, chips and the hero card. Never put glass on glass. Content sits on plain surfaces (`--fill-surface`).

**Team colors** are the source's where it has one (black and white included), remembered by team ID from every payload (`state/logoColors.ts`, `applyColors`), so a page opened from a schedule row without colors paints right; a team with no source colors at all (CS2) wears its crest's, read once and cached. A game's colors are decided once (`data/matchColors.ts`, MatchColors.swift): each team has its identity (the club's color: the hero's wash and crests, a tile's wash, `identityPalette`) and, for this game, a kit (what its men wear and what every mark of theirs is drawn in: charts, the docked bar, end zones, the theaters' figures and tags, today's and the engine's alike, and a replay's under its row, `matchPalette`, `uniform`), so the chart and the field can't name opposite teams. The kit is ESPN's match-day uniform where the soccer summary has one (`GameDetail.matchKits`, held from kickoff by `noteDetail`), else the team's color. Home keeps its kit; on a clash (OKLab under 0.12 in either scheme, as marks or as worn) away changes: its kit's second color, then its team's, then white (charcoal against a pale home). The decision is the same in both schemes; `teamPalette` only tones (only lightness moves; a color with no usable hue is an honest gray). Use them for washes and marks, never text.

## Motion

The rules, from Components.swift `Motion`:

- **Should it animate at all?** Anything triggered from the keyboard doesn't: highlights, view switches with ←/→, section toggles via Enter, and pages reached by keyboard, which arrive with `state.viaKeyboard` and no entrance. Neither does anything that happens tens of times a minute.
- **Springs never bounce.** In `motion.ts`: `spring.quick` (0.2), `standard` (0.3), `travel` (0.4). Use them through `motion`'s `m.*` components inside the app's `<LazyMotion>`, whose features load after first paint.
- **Curves and durations** for CSS are in tokens.css: `--ease-out` (Emil Kowalski's strong ease-out) for entering, leaving, fades and presses; `--ease-in-out` for changes of light. Durations: press and exit 120ms, fade 150, quick 200, reveal 250, standard 300. Exits are faster than entrances. UI motion stays under 300ms. The one exception is ambient decay (the score flash fading over 1.2s), which nothing waits for.
- **Interruptible.** Use CSS transitions or springs that retarget from the current value. Never block input while something moves. Use keyframes only for one-shot entrances.
- **Only transform and opacity move.** The strips place marks with `cqw` units in a transform for this reason.
- **Reduce Motion:** anything that moves becomes a short fade, never nothing. CSS modules carry `@media (prefers-reduced-motion: reduce)` variants, and `MotionConfig reducedMotion="user"` covers motion.
- **Hover** styles sit behind `@media (hover: hover) and (pointer: fine)`.

What's built:

- **Page entrance:** blocks slide 10pt from the left and fade, cascading (`stack-in`). Keyboard arrivals don't.
- **Collapsing or expanding a section or tier by click** runs in two phases, like ScoresView.toggle. First the crests are linked and layout tracking turns on; on the next frame the section toggles. The crests then travel between the rows and the collapsed preview (shared layout), the sections below glide (layout spring), and the rows' text rises in, staggered 40ms per row and capped at four. A toggle within 450ms of the last, or from the keyboard, is instant.
- **Live:** a score change flashes the row (a soft red wash plus the scorer's dot) or the tile digit (a red pill), and the digits roll. Clocks tick on the second. Dots breathe in phase.
- **List ⇄ Tiles:** a click stacks the new view in; the keyboard switches instantly.
- **Menus:** a pull-down grows from its trigger, a context menu from the corner nearest the pointer (both 96% → 100% on the quick curve, out on the exit's); keyboard opens are instant. Move Up, Move Down and Hide glide the sections to their new order (`rearrange` in `features/scores/sections.tsx`). A tile's hover "…" arrives from 92%.
- **Strip moments** (TileStrips.swift), each a layer that exists only while it plays, on a visible page only: a touchdown lights the end zone it went into in the scorer's color on the flash's timings; a change of possession swings the chevron 180° over the ball, crossfading colors (Reduce Motion: a crossfade in place); a run scoring pings home plate and a goal pings in its team's color (`Motion.ping`: 0.6× → 1.8× over 600ms; Reduce Motion: a softer ring fading in place); a new goal or card arrives like a badge; a map won empties the CS2 race with a ghost of the won cells leaving on the exit's timing.

The owner can run `/review-animations` on the motion code for an independent review; agents can't invoke that skill.

## Layout, navigation and keyboard

- **Phones** (under 760px): one column, at most 440pt, like the Mac panel. The window scrolls; headers are sticky, with a soft scroll edge once content is underneath.
- **From 760px:** a split view. The scores are a glass sidebar (340–420pt, the Mac's compact and medium widths) beside a detail pane, each scrolling on its own. The sidebar stays mounted across pages, so it keeps its scroll, highlight and polling, as the Mac keeps Scores built under every page. With nothing selected, the pane says "No Game Selected" (Mail's pattern).
- **Width classes:** blocks add detail as they widen, from the Mac's thresholds of 380pt of content (medium), 460 (large) and 560 (xlarge). `useWidth(ref)` gives a block's width in points from one ResizeObserver. The scores list follows `data/listLayout.ts` (12pt of hysteresis): rows show records from medium, the team block fixed at 230pt so scores keep one column; from large a detail lane between score and status takes the situation over the context, a line each; from 680pt the rows sit two up, compact, the arrow keys moving around the grid by section, and crossing the split they fade in at their new places. (Today's sidebar, 340–420pt, and phone column, 440pt, stay compact or medium.) Tiles go to 3 small columns from large, and 4 small plus 2 large from 680.
- **Routes** (`src/app/App.tsx`): `/`, `/game/:id`, `/sports` (every sport, a Following row, one search across competitions, tournaments and teams), `/sports/:sport` (a sport's leagues, cups, tournaments, circuit and teams), `/following`, `/sports/competition/:id` (a competition's schedule, Explore and settings: one team list, the star follows, Selected Teams picks), `/settings`, `/settings/league/:id` (legacy alias), `/team/:id`, `/player/:id`, and the schedule world, built by the helpers in `data/schedule.ts`:
  - `/schedule` (everything), `/schedule/your-teams`, `/schedule/<league>`, `/schedule/team/<id>?name=&logo=`, `/schedule/climbing`, `/schedule/tournaments`; each faces back in time with `?mode=results` (`schedulePath`).
  - `/results/climbing/<event>/<dcat>?category=&event=` and `/results/tournament/<slug>?name=` (`eventResultsPath`).
  - `/standings/<league>`, `/rankings/<league>`, `/bracket/mlb/<year>`, `/bracket/cs2/<slug>?name=`, each with `?ring=<team ids>` for the match it was opened from (`standingsPath`, `rankingsPath`, `bracketPath`).
  - A game's link should carry its league so the page loads even when the game isn't on today's scoreboards: `gameHref(eventID, leagueID)` (features/game/core/useGame.ts) gives `/game/espn-401908043?league=mlb`. Game pages link players with `PlayerLink` and `espnPlayerRef(path, id, name)` (At the Plate's batter and pitcher) and teams as `/team/<competitor id>`.
  - Team and player pages: build their paths with `teamHref` and `playerHref` (or drop in `TeamLink` and `PlayerLink`); the formats, and the older ones the pages also accept, are in [Team and player pages](#team-and-player-pages).
  - Every route but the scores is lazy; a link straight to one paints the shell's frame (`ShellFrame`) while its chunk arrives. To add a page: create `src/features/<area>/<Page>.tsx` that exports the component, point its route's `lazy` at it, use `PageHeader` with `<PageBack />` as its leading control, and use `useScoreboard()` or a new query for data.
- **Back** (`useGoBack`) returns to whichever page opened this one. A page opened directly goes back to the scores. Esc does the same from anywhere except a text field. `PageBack` (every page header's Back) names the page it returns to, as RootView's `backTitle` does: "Scores", "Schedule", "Results", "Match", "Table", "Top 25", "Bracket", "Season", a league's short name, an event's name (`app/backTitles.ts`), or a team's or player's name, which those pages give themselves (`useOwnBackTitle`). A trail of visited history entries (`app/navigation.ts`, kept in sessionStorage) supplies it; a navigation's `state.from` still wins (a roster's links say "‹ Chiefs"). Beside the sidebar it hides only when the sidebar is where it leads: a page opened from the scores or picked in the sidebar. A "Skip to Page" link is the first stop for a keyboard there, past the sidebar's games.
- **Keyboard:** on the scores, ↑/↓ move the highlight (←/→ too in Tiles, by on-screen geometry), Return opens the game, P shows it in the tab (the Mac's ⌘P), Shift-F10 or the Menu key opens a focused game's menu, Esc goes back. The keyboard highlight wears the accent; the pointer's hover is a quiet gray and takes the highlight back.
- **Commands** (`app/commands.ts`, PanelCommands.swift): R refreshes every query on screen, comma opens Settings, S opens the Schedule. The Mac's ⌘R, ⌘, and ⌘U are the browser's, so these are bare keys; they stand aside while typing, with any modifier, inside an open menu, and for a key a page already took. Header buttons name their key in the tooltip ("Refresh (R)"); Settings → Keyboard lists them all (pointer devices only).
- **Context menus:** a game's (`features/scores/GameMenu.tsx`; its items load as their own chunk, warmed at idle) and a section's (`SectionMenu.tsx`) open by right-click, by the "…" that shows on hover (always shown for sections on touch), and by a long press on touch (480ms, 10px of slop, a tick of `navigator.vibrate` where there is one; the tap that ends it is swallowed, and the link's own callout is off). Build menus from `MenuEntry`; open one at a point with `ContextMenu`.
- **Scroll memory** (`app/scrollMemory.ts`, RootView's `scrollMemory`): beside the sidebar, the detail pane scrolls on its own, so it keeps its own memory: a fresh visit starts at the top, Back and Forward land where the page was, and the same page turned the other way in time (Upcoming | Results, a replace on the same path) keeps each way's place. On a phone the window scrolls and React Router's `ScrollRestoration` does the same.
- **Schedule pages:** ↑/↓ through the rows, ←/→ step the navigator (a day, a week, a month, a round), Return opens, T goes to Today (Results: the latest round), ⌥1 / ⌥2 face Upcoming / Results (the Mac's ⌘1 / ⌘2, which browsers keep for tabs). The page in front takes the keys (capture phase) unless focus is in the sidebar.

## Game pages

A game's page (`features/game/GamePage.tsx`, DetailView.swift) is a core that every sport shares and one hook per sport. The core owns what's common; a sport owns its sections and its live lane.

**What the core does**

- **The event and its detail, by ID** (`core/useGame.ts`). The hero shows as soon as the event is known; the sections assemble when the detail arrives. The event is the scoreboard's copy when there is one (it stays live with the sidebar's polls); otherwise it's built from the game's own ESPN summary (`eventFromSummary`), with the league from `?league=` or, failing that, every ESPN league asked in parallel. The detail (`GameDetail`, data/gameDetail.ts) is one TanStack query per game on DetailView's cadence: 30 s while live with a fast lane, 15 s without, 2 min otherwise, once for a final more than six hours old, 5 s after a failed first load. Two failed refreshes on a live game make it stale: the hero says "Can't connect · Updated 10:42 AM" and the live dots hold still. A CS2 match off the scoreboards (`/game/cs-132237` from a schedule, a bracket or a team page) is bo3.gg's match by ID, S-tier only, kept current by its own detail loads; a climbing round of a discipline Settings hides is never fetched.
- **The section plan** (data/sections.ts). `sectionOrder(ref, state)` is the Mac's single-column order per sport and state: the Live View (live only) leads, Win Probability opens every page that has it (right under the Live View), then the chart it replays for; `widePlan` is its two-column plan from 680pt of page (12pt of hysteresis), linked partners side by side, Win Probability at or near the top of its column; `wideArrangement` places what's shown, never leaving a column empty, each column in the user's order. A section with nothing to show leaves no hole.
- **Modules** (`core/usePageModules.tsx`, `core/modules.tsx`, `core/moduleDrag.ts`, `core/CustomizeModules.tsx`; PageModules.swift, ModuleDrag.swift). Every section is a module: `DetailSection` reads the page's `SectionChromeContext` and draws its header as a disclosure (`h2 > button`, `aria-expanded`; the whole header is its target, a 6% wash on hover drawn under the click, the chevron at its edge). Folded, a module keeps its place and one live line in its own terms (`SportPage.glance`, else `core/moduleGlances.ts`; a chart's moment while it's news, so a folded chart in view carries it and the docked bar doesn't), read as the header's description; the Live View folded keeps its theater mounted and unseen (`hidden`: no frames, its running order kept) and the chart it left takes back its bursts (`useModuleOpen`). Space and Return toggle, ← folds, → opens, ⌥-click folds or opens them all, ⌥↑/⌥↓ move (announced); keys don't animate; a click glides the page on `standard` (layout tracked a frame before the change, 450 ms); Reduce Motion fades. The menu (right-click, Shift-F10) collapses, moves, hides the module on the sport's pages or opens Customize; the page's end names what's hidden, with Show. A mouse press that travels past 4pt lifts the module (`ModuleDrag`, outside React): the page folds to its headers for the drag (never saved), the header rides the pointer in a fixed layer (its transform written per move), the module holds its gap under a faint well, the others slide (`layout="position"`), the edges scroll (`autoscrollSpeed`), Esc puts everything back, and release saves the order within its column. Customize (its own chunk) lists every module of the sport's pages (the Timeline on every ESPN sport's, under Win Probability) with a checkbox and a handle (drag, or ↑/↓ on it, announced) and Restore Defaults. Folds, hides and the order are the settings' (the Mac's keys).
- **The hero** (`core/Hero.tsx`) with the scoreboard's beats, decided by `HeroBeats` (data/matchRules.ts): a score's digits pop over a pill in the scorer's color when the number actually changes (whichever of the moment and the number arrives second fires it), the scorer's side of the wash lifts and settles, and a decisive score or the final whistle sweeps one glint. The final whistle is announced. Full plays all of it, Subtle keeps the pill, Off keeps nothing that moves.
- **The docked scorebar** (`core/DockedScorebar.tsx`, `core/geometry.ts`, `core/possession.tsx`). A zero-height sticky slot under the header holds a glass bar with the score, the clock and the sport's detail. The detail and the chip fit like the Mac's ViewThatFits over three rows (the fullest the width tier allows, then the short text with the chip, then the glyphs alone), measured off screen. A sport with possession (`SportPage.possession`, football and the NBA) gets a slot beside each team that keeps its width; when the ball changes hands live it glides across, or for a turnover whose field can't be seen it's tossed on a low arc, spinning a turn and a quarter and landing with a knock (`possessionMotion`, `tossAt` in data/matchRules.ts); Reduce Motion crossfades. One passive scroll listener turns the position into a 1/64 dock step and writes the bar's (and the hero card's tuck's) `transform` and `opacity` only when the step changes; React hears only the surface flipping at half docked (which scoreboard plays the beats and ticks the clock) and sections crossing visibility thresholds (a captioned moment whose chart is out of view takes the bar's status slot: the news line). The glass takes the opacity itself: an ancestor with opacity would leave the blur nothing to see. A click goes back to the top.
- **Moments** (`core/moments.tsx`, data/moments.ts). One slot per page: the most important moment wins, a catch-up plays only its newest score, a lesser one never interrupts a greater one, scores hold 6 s (others 4 s) and are announced politely. Charts read `useChartMoment(chart)` and caption it under themselves (`ChartFooter`: pointing beats news, news beats the legend).
- **Celebrations** (`core/CelebrationStage.tsx`, data/celebrations.ts). A canvas over a chart plays a moment's cue: confetti, fireworks (baseball), sparks, swish, rim pulse, embers, or with Reduce Motion a soft bloom. Particles are closed-form functions of time, at most 36 per burst; requestAnimationFrame runs only while one plays. Subtle and the 10 s cooldown trade confetti and fireworks for sparks; Off draws nothing; pointing at a chart wins (a burst yields to the pointer).
- **The scoring slide** (`core/scoringSlides.tsx`, its rules and words in data/scoringSlide.ts; ScoringSlide.swift, ScoringSlideView.swift). When a team scores on the open page, a broadcast lower third in its colors slides in from its side of the hero (the top team's from the left) while the hero's scoreboard steps aside: three hard-edged layers, no rounded corners. A kicker tab in the team's second color says who and when (`kicker`: "BREWERS · TOP 12TH", "BOT 9TH", "12TH INN" for an unknown half, "2ND QTR", "OT", "2OT", soccer's "67'", "90+3'"; the inning's half is ESPN's `period.type`, `ScoringFacts.half`). The slab in its color holds the logo in a darker zone behind a slash, a headline in SF Pro Condensed Black Italic caps (HOME RUN, 2-RUN HOMER, GRAND SLAM, RBI SINGLE, TOUCHDOWN, FIELD GOAL, PICK SIX, GOAL, PENALTY, LATE WINNER, BUZZER-BEATER, GO-AHEAD 3-POINTER, MAP WON, MATCH WON, TOP, NEW LEADER) and, at its far end, the tally: both rows of the new score, the scorer's first (`tally`; the single score line where there's none, as for CS2's maps). A near-black detail strip says who and how from the lanes' own accounts (`LiveMoment.facts`, data/scoringFacts.ts: "Pratt · 396 ft · EV 99.1 mph", "D. Pierce 5-yd run · PAT good", "Haaland · header · assisted by Ndiaye", the minute being in the kicker), and a "+N" chip sits on the kicker row over the tally. Every slanted edge (the slab's, the kicker's and the strip's far ends, the logo zone's edge and its slash, the chip) leans with the italic, 12°, on both sides: the right team's graphic mirrors in place, never in lean. The moment slot hands each batch to the page's `ScoringSlides` first (`MomentSlot.attach`): its scores join a line (in order, never stacking; a catch-up only its newest; at most three waiting; a retraction pulls its slide), and each slide makes the one polite announcement (the slot stays quiet for it). Tiers: a slide; a sheen and a spark at the logo (a home run, a touchdown, a goal); a 6 s hold (else 4.5) and confetti (a grand slam, a walk-off, a pick six, a late winner, a buzzer-beater, a match won). One burst per moment: the theater or chart that owns it plays the page's burst when it's on screen, else the slide does (`playsConfetti`); a moment no chart bursts for claims the 10 s cooldown (`MomentCenter.claimBurst`); level, cooldown and Reduce Motion as every stage. Timing: when the play's theater is on screen replaying it, the wipe starts 0.2 s before the replay's climax (the ball over the fence or the first runner home, the touchdown, the net), read from the script the stage replays; each theater registers with `useSlideTheater(chart, playing, climax)` (mlb/theater/slidePlate.ts, football/theater/slideField.ts, soccer/theater/slidePitch.ts; the NBA's court theater hooks in the same way once the web has it). The motion is a pure timeline (`SLIDE_IN`, `SLIDE_OUT`, `slidePose`), played as WAAPI on transform, opacity and the reveals' clip, every layer on one clock: the kicker in from off its entering edge (0–0.26 s), the slab (0.05–0.44) and the detail strip (0.12–0.50) on a crisp ease-out, the logo popping (0.22–0.52), the headline and the subline revealed behind a moving edge on the italic's own lean, travelling away from the entering side (0.24–0.56, 0.30–0.64), the tally rising (0.36–0.60), the chip popping (0.44–0.70), one sheen across the slab (0.34–1.05); nothing moves during the hold; out the way they came, the strip first, the slab 0.04 s after, the kicker 0.08 s after, the chip fading, gone by 0.38 s; Reduce Motion crossfades. Two hosts overlay without moving anything: over the hero card (`Hero`'s `overlay`), vertically centered on it, bleeding into the page's 10pt gutter on its entering side, its far end 16pt short of the card's and the slab at most 560pt (a lower third, not a banner); there the card's glass and everything in it fade out (0.18 s) while the host is in the tree (`data-slide-host`, a `:has()` rule in Hero.module.css) and back (0.25 s) only once the graphic has gone. Or in a zero-height sticky slot under the docked bar once that's the scoreboard (the bar stays); whichever surface is on screen draws, and a slide moved mid-hold doesn't come in again. The docked bar's news line yields to a score the slide tells, and the hero's decisive glint to its sheen. Paint: the team's color (its second when the first is black or white), lightness clamped in OKLab, white or near-black type by WCAG contrast (white at 4:1, the headline being large type), the kicker and the chip in the second color, their type the slab's own color where it reads there (4.5:1) else near-black or white (`kickerInk`); the same in light and dark, as a broadcast graphic is. Web addition: the tally's other row keeps its softer ink (55%) only where it clears 4.5:1, else the next step up (`smallInk`). Sizes by width class (kicker, slab and strip heights; the headline): 18/48/19 and 36, 20/54/21 and 42, 21/58/22 and 46, 22/62/23 and 50; the rest scales with the slab. Type fits as ViewThatFits and minimumScaleFactor do, measured once per slide and width from each line's container: the short headline, then down to 40%; the subline down to 90% in its strip, then (a web addition, so a phone doesn't cut the play) the strip runs the slab's whole length and the subline goes to 82%. The type is `system-ui` with `font-stretch: condensed` (SF Pro Condensed, as WebKit draws it); Chromium's system font won't condense, so there it takes Helvetica Neue's condensed faces (Arial Narrow, Roboto Condensed elsewhere), checked once per page. Settings → Live Games → Scoring slides, on by default.
- **Sounds** (`core/sound.ts`, the rules in `data/celebrationSound.ts`; Celebrations.swift `CelebrationSound`). Opt-in (Settings → Live Games → Sounds), never with Celebrations off: the moment slot plays one as it shows a moment, so sound and picture start together: a soft pop for a score on the open page, glass for a decisive one, nothing below score tier, at most one every 8 s. The Mac plays the system's Pop and Glass, which it doesn't ship, so both are synthesized with the Web Audio API (a sine dropping two octaves in 80 ms; three inharmonic partials over G6 ringing out in a second), from silence to silence. Browsers start audio suspended: the game page unlocks it on the first press (`listenForUnlock`), and the Sounds switch as it's turned on; a sound that can't play yet is skipped and doesn't use up the 8 s.
- **Shapes as well as color** (Settings → Appearance; the Mac's Differentiate Without Color, LiveViews.swift `shape`). The bottom team's marks on the pitch and the spray chart are rounded squares in the same box as the top team's circles (`core/shapes.ts` `markPath`), its last-touch ring dashed, its legend swatch square; CSS keyed on `html[data-shapes]` dots a penalty's drive bar and dashes a turnover's, makes CS2's bottom team's rounds capsules, and half-fills a draw in a form strip.
- **Chart labels** (`data/chartLabels.ts`, `core/chartLabels.tsx`). Team labels in charts never spill: a gutter grows from the Mac's 30pt to 44pt for a long one (`useLabelGutter`), then the label shrinks to 80%, then it's cut at a whole character with an ellipsis and its full name in the tooltip (`fitted`, `FittedName`; the soccer timeline, the game flow, CS2's rows); HTML labels in fixed slots cut with CSS (the line score, win probability, the docked bar, the end zones).
- **Linked focus** (`core/linked.tsx`). One store per page, outside React: `Focus` (a play, a period and side, an athlete, a player, a span). Rows report hover with `useLinkedRow(focus, { pinnable })` (a row holding links, `{ pinnable, links }`, pins on a click beside them and isn't a button itself, so its links stay links), canvas marks with `useLinkedMarks(points, focusOf)`; readers subscribe to one primitive with `useFocus(selector)`, so a hover re-renders only what it lights. Links show once the pointer settles (80 ms) and follow it at once after; a click pins; Esc unpins before it goes back.
- **No section older than the header** (`core/headerSync.tsx`, data/headerSync.ts, state/laneScores.ts; web, from the live check): the header reads the fast lane every few seconds, the summary-driven sections ESPN's slower summary. The page keeps a ledger of what its header said, period by period (the lane's clock or the scoreboard's period, else the inning in its text), and the line score is brought up to it while the summary trails: each period's cell at least what the header said at its end, the period under way taking the rest when the line has its column, the total the header's; columns aren't made up, and a summary caught up or ahead shows as ESPN has it. A lane's score ahead of the scoreboard's is published for the scores list beside the page, whose rows and tiles show it until the scoreboard catches up (three minutes at most); alerts and the tab's title keep to the polls.
- **The fast lane** (`useFastLane(active, interval, tick)` in `core/sport.tsx`): one tick at a time while live and the tab is visible, 5 s apart (soccer 8 s, climbing 4 s), catching up when the tab returns.
- **Shared sections** (`core/useCommonSections.tsx`, `core/CommonSections.tsx`): the line score (cells light their plays; extra periods scroll between names and totals, starting at the latest), win probability (with live odds: below), the timeline (every sport's: below), team stats (split bars, two columns from xlarge), scoring plays or key events (pinnable rows), the latest plays, where to watch, and the postseason series (`momentText` renders a scoring play's words, so football links its players' names and soccer a goal's scorer and its assist). `DetailSection` is the titled block (title, accessory, caption, spoken caption) and a size container (`@container section`), so a chart adds detail by its own room; `VizWell`, `ChartFooter`, `Legend` and `LegendItem` are the chart chrome.

**Win Probability with live odds** (`core/odds/`, `data/odds/`, `state/odds.ts`; ODDS-SPEC.md and the Mac's ODDS-DECISIONS.md; OddsChart.swift, Odds.swift and OddsFeed.swift ported at HEAD, 5364680 onward): Polymarket's live market, a line per outcome, against ESPN's model and DraftKings' pregame line, in every ESPN sport's Win Probability, also on finals ("How the Odds Moved") and before the game (the market's last day, first on the page). The timeline sits beside it in the same column, on the same clock.
- **Data.** The game's market is found as the page opens: the league's day from Gamma without its markets (`include_markets=false`: 8 KB where the full listing is 20 MB), kept 10 minutes and shared by every game that day; the one main event (its slug ends with the date) whose two teams both fit ESPN's (`OddsMatch`: names as words, club affixes and numbers dropped, local names to ESPN's, scored 3/2/1, one team to each side, the better reading strictly better) and whose start is within 6 hours, an hour nearer than any other; then only its moneyline (`/markets/slug/<slug>`; soccer `/events/slug/<slug>`: three Yes/No markets). A match is kept for the session, "no market" for 10 minutes. ESPN's half comes from the summary the page already polls (`GameDetail.odds`): each `winprobability` entry joined to its play by ID and put on that play's wall clock, in exactly the timeline's chronology (`data/odds/chronology.ts`: soccer's commentary by wall time, the current drive's overlap dropped, scoring plays slotted in, and a late stamp moved only as far as staying in order needs, the longest run in order standing as reported), the periods, the notable plays, DraftKings (provider 100) with the vig removed.
- **Live.** The CLOB socket only while the section is on screen (0.25 s on, 2 s off) in a visible tab, one tracker app-wide; the socket closes when the section leaves, the tab hides or the page closes, reconnects with backoff, and after two failed connects polls the midpoint every 15 s. History is what the chart is missing (`holes`: the game's opening, its tail, any stretch a `GAP` of 6 minutes long), each asked for once (a hole answered with nothing stays answered) and merged without overwriting a live tick (`mergingHistory`); a failed request is asked again with backoff while the chart stays on screen; every (re)connect asks for the tail. The shown price is Polymarket's (`displayed`): the midpoint, an empty side being the contract's bound (no bid is 0, no ask is 1), or on a book wider than 10¢ the last trade, but only a trade since the book was last tight (a book breathing around 10¢ never saws back to an old trade); a book's `last_trade_price` is ignored (it isn't asset-scoped: the Ravens–Bills capture). Ticks reach the chart at most twice a second, every outcome at one instant (no microsecond intermediate soccer splits), on a 0.1-point move; a quiet observed stretch holds flat, but after a `GAP` nobody saw the line starts afresh (`publish`); a series keeps at most 600 points (the last 10 minutes as they came, older a minute each); a quiet market's price is repeated at now once a minute (when 50 s old). The feed is the page's (`useOddsFeedObject` in `useCommonSections`), shared by the timeline (its newest tick, `latestTick`) and the section.
- **The chart** (`OddsPlot.tsx`, `drawOdds.ts`, its data and geometry in `data/odds/chart.ts`), following Polymarket: one line per outcome on a fixed 0–100% scale, each in the color its team wears in this game (the page's palette, decided once by MatchColors, as the timeline's marks are: one model, so a clash can't color them differently) held to 0.10 OKLCH chroma (`lineColor`; soccer's draw a neutral that recedes, #aeaeae light, #5d5d5d dark), broken over unobserved stretches, each ending in a dot (smaller on a final) and a label (name and chance) in a column at the right that dodges its neighbors as a cluster (`OddsLayout.dodge`), keeps its outcome's place through a near-tie (`nextEndOrder`), dissolves before a collision, glides with the dots, and leads back to a displaced dot when that's unambiguous (`endLeaders`). Two canvases: the still layer (grid, period dividers, every line up to its newest point) redraws only when the data, the size or the colors change; the live ends (the last stretch, leaders, dots) draw per frame only during a 0.5 s glide (Liveline's 8%-a-frame curve, from what's on screen, never a hook back to history: `tailConnector`), not for a move under a point. Every end pulses on one shared phase while the market streams and the chart is seen (CSS animations; the outcome that just moved beats brighter on the next beat, after its glide lands); a final, Reduce Motion or off screen: still dots. The legend is the header: each outcome's chance, summing to 100 (`percents`: largest remainder, never 0 or 100 until it's over, and only Latest and the exact final endpoint show 0/100: `usesFinalPercentages`), and the muted line under it (ESPN and DraftKings for the top team, the longest wording that fits; a final's, where it began). The footer: "Live · 4s · $4.1M traded" and "Polymarket ↗". Game and 10 min windows while live; zoomed to a period, "Whole Game". The plot's 0/50/100 labels and the period (or, before the game, hour) labels under it; the period labels are buttons that zoom both modules. Screen readers get a table twin (each period's start and the latest, every outcome's chance, ESPN's).
- **Inspection** (`core/odds/inspection.tsx`, `data/odds/pointer.ts`; OddsPointer, MatchInspection, MatchInspectionActions, MatchPinControls, MatchFocusLink): one moment per page, read by both modules. Four things ask for a reading and the first with an answer wins: a row or mark linked on the page, the pointer over a chart, the keyboard's reading, the pin. The pointer reads and its reading ends as it leaves, whatever has focus; a click holds the moment, or the key play it's on (the same pin as its row), and again lets go; ←/→ step 1% of what's shown, ⌥←/→ walk the key plays (bringing the game back from a zoom to show one), Return holds, Esc lets go, then unzooms, then the page goes back; Home/End reach the ends (a web addition). Pointing reads that moment into the legend, the muted line (only what doesn't change with the moment) and the footer ("Q3 4:12 · GSW 62% · ESPN 58%" and the play: never an upcoming one, and no odds across a stretch nobody observed), and a 1pt crosshair with a dot on every line; the live ends step back to 25%. Held, the footer offers the previous and next key play and Latest. Each plot is a slider for assistive tech whose value is the reading ("Held, 7:42 PM. GSW, 62 percent. MIN, 38 percent."). A key play's row hovered moves both charts' line, pinned holds them (`useFocusLink`). Only the small readers subscribe to the moment (`usePointer`), so a move re-renders nothing else.
- **The timeline** (`core/timeline/`, `data/odds/history.ts`, `marks.ts`, `timeline.ts`; MatchTimeline.swift, MatchHistory.swift at HEAD, fdae434): one timeline for every ESPN sport, and it's soccer's: one track, each team's marks in its own lane (labeled), half-time and the breaks marked at their real width, time played filled while live and a now dot. The marks are the page's key moments by the rows' IDs (`timelineMarks`): soccer's goals and cards, the NBA's curated Key Plays, the scoring plays and baseball's runs, football's turnovers (in the lane of the team that gave the ball away); a period's end is a landmark, not a mark. The axis is the wall clock Win Probability uses (`OddsLayout` at the same width and the same labels' column, the well's 8pt inset matched), so a goal sits above the odds it moved; on match minutes only when soccer has no timestamps. A live axis is the game's usual length from its first play (`Pace`: soccer 113 min, MLB 165, NFL 185, college football 205, NBA 155, WNBA and college basketball 125), growing a quarter hour at a time past it, so marks hold still and the odds line ends at now; a final ends at its last play. Soccer's clock against the wall (`SoccerClock`): 0', HT and the end, quarter hours with room, the second half pencilled in before it's played; other sports name their periods, and zoomed to one show what the game clock said as it went by (an inning: its two halves). Pointing at a mark lights it and its row and the labels' row says what it was. While the page broadcasts, both modules read the same `until` (p when they last redrew: `PresentedTime`, redrawn when p reaches the next pending tick or every 15 s for the now line, never per frame), and the presented history is cut at p with only told plays (`Broadcast.presentDetail`).
- **Fallback.** Odds off, a league Polymarket doesn't list, or no confident match: ESPN's bar exactly as before.

**Adding a sport** (the seam is `core/sport.tsx`):

1. Port its detail into `GameDetail` (data/gameDetail.ts or `data/<sport>.ts`) and its live lane into `data/liveFeeds/<sport>.ts`, pure, with fixture tests. A lane is a class with `update(fetcher, …)`, `subscribe` and `takeMoments()`; replace fields only when they change.
2. Write `features/game/<sport>/<Sport>Page.tsx` exporting `use<Sport>Page(game: GameContext): SportPage`. Call `useCommonSections(game)` for the shared sections, add the sport's own (each a `DetailSection` keyed by its `Section`), run the lane with `useFastLane` and offer its moments to `game.moments` (and its retractions to `game.moments.retract`), and return the hero's clock text and second line, a lane's live clock (`clock`, when it reads closer than the scoreboard), possession, the docked bar's detail (`dockDetail(tier)`) and a chip. Optional: a shot in the air (`possessionInAir`: the ball dims in the hero and on the bar), a chip beside the hero's clock (`heroChip`), a line under the hero's status in any state (`heroNote`), and what sits beside each team's name on the docked bar besides the ball (`dockSlot(side, tier)`: soccer's red cards). `features/game/mlb/BaseballPage.tsx` is the worked example; `nba/BasketballPage.tsx` uses most optional fields.
   A field event (climbing) can also return its hero line from its own lane (`fieldSummary`: "Final · Leader 🇸🇮 L. Rakovec" from the round's ranking, so the hero names the climber the results rank first while the scoreboard's copy lags), the colors its wash takes (`wash`: a climber's flag, crossfading like a change of light) and the docked bar's lead in place of its title (`dockLead(tier)`); any sport a badge under the hero (`heroBadge`) and a trophy (`trophy`: beside a series winner's name, or on a decided final's winner line, bouncing when won on the page).
3. Register it in `SPORT_PAGES` (`features/game/sportPages.ts`) under its `PageKind`, as a dynamic import (`kind: () => import("./x/XPage").then((m) => m.useXPage)`), never a static one: each sport's page, charts and lane are their own chunk, so a soccer page doesn't download the NBA court or the MLB theater (`test/unit/bundleSplit.test.ts` holds the line). ## The game as one broadcast

A live ESPN game (NBA and WNBA, NFL and college, soccer, MLB) is told as one broadcast ([BROADCAST.md](../docs/engine/BROADCAST.md), Phase A as implemented on the Mac): one event-time-ordered timeline per game, a presentation clock `p = now − D` that never presents past what's known, and everything on the page but the theaters reading the game as presented at `p`. So the score changes as the play is told, never before, and the hero, the docked bar, the lists, the charts, the tab and the alerts never disagree. Ported line for line from the Swift at HEAD (1.0.33), with BroadcastTests.swift ported check by check:

A play the theater's newest plan didn't cover waits for its anchor `coverWait` (5 s) after it arrived, then the timeline's fallback tells it and notes it.

**Where the web differs, and why:**

- A hidden tab is the Mac asleep: nothing is scheduled while it's hidden, the tab's title and the alerts go back to the scoreboard's (the lanes pause too, so the page would only stall), and coming back more than 30 s later is a wake: the live edge, with the floor raised to what the tab showed meanwhile.
- The behind-live readout has no number for a delay that isn't one (Swift's `Int(…)` would trap on it); revision digests are a 53-bit string hash (Swift's `Hasher` is seeded per process; only equality matters).
- The summary's Latest lines carry no play IDs on the web, so an NBA page shows them only while the timeline knows no plays; otherwise it lists the told plays, as the Mac.
- The theater's disagreements (an order guard overridden, a play told without its anchor) are logged to the console in development only (the Mac's `Log.theater`); the counts are on the timeline.
- The `?demo` harness's recorded plays carry their game's own wallclocks, days old, which no presentation clock can present live: its pages don't broadcast (`data/broadcast/switch.ts`), unless `?demo&broadcast` restamps the NBA replay onto the harness's clock (`/game/espn-401909869?demo&league=nba&broadcast&nba=10`; `test/e2e/broadcast.spec.ts`).
- A stoppage at a period's end (a team rebound or a review at 0.0, and the period's end ESPN stamps with it) is bounded by the next period's start once a play of that period is known (`GameTimeline.restart`). The Mac looks for the restart only in the stoppage's own period, finds none, and falls back to the cluster's arrival: on a page opened after such a period, the moment the page opened, which holds the period's end and every play after it until p gets there ("0.0 left in the 2nd, Under review" through a live 4th, POR @ PHX, 2026-11-05). Live, nothing changes: until the next period is known, the arrival still bounds it. Tested on a real slice (`test/fixtures/broadcast`, DAL @ SA opened in a timeout in the 3rd); the Mac has the same code and the same bug.
- The timeline and the odds read `broadcast.clock` through one presented time per page (`PresentedTime`), so both draw the same p.

## The tab, alerts and the installed app

What the Mac's menu bar item, Notifier and panel do, a browser does through the tab, Web Notifications and a manifest. `app/LiveServices.tsx` runs beside every page (loaded after the first paint, rendering nothing).

- **The tab's live score** (MenuBarLabel.swift; `data/tabScore.ts`): the pinned game, or else (Settings → Tab → Live score) the first followed live game in your league order, or a followed final for ten minutes. The title leads with "ARS 2–1 CHE · 67'" ahead of the page's own title (`setTitleScore`, composed in `app/useDocumentTitle.ts`; a page that is that game keeps its title), and the favicon draws the score on the icon's night (`app/favicon.ts`: "2–1", or two stacked scores past three digits, a red dot while live). A pin lets go four hours after its game, once over. While that game's page broadcasts, the tab shows it as the page presents it (`state/presented.ts`, `menuBar`: [The game as one broadcast](#the-game-as-one-broadcast)), and so does the page's own title.
- **Alerts** (Notifier.swift; words in `data/notifier.ts`, delivery in `state/notifications.ts`): each poll is compared with the last for games involving a followed team: "Started", "Goal · 23rd minute", "{Team} scored · 3:10 left in the 2nd", "Score updated · …" for a correction, and the final ("Full time"); a final without scores is a postponement and says nothing. One alert per game (`tag` is the event ID, with `renotify`), titled with the score line. Several open tabs post each alert once (a Web Lock around a note in localStorage). Permission is asked only from Settings → Notifications, which shows the browser's answer and stays current. A click focuses the tab and opens the game (`gameHref`): through the service worker's `notificationclick` (which posts `{ type: "open", path }` to the tab) when one is installed, else the page's own `Notification.onclick`. While a game's page broadcasts, the scoreboard's alerts for that game wait (`alertsFollowPage`) and the page sends them from its presented changes (`notifyPresented`), so an alert never tells a play the page hasn't.
- **They work while a tab is open**, even hidden: the shell's reader keeps polling a background tab while alerts are on, a game is pinned or a followed team's score belongs in the title (browsers throttle hidden timers to about once a minute). **Push**, for alerts with no tab open, would need: a Worker cron that polls the followed teams' leagues and diffs them (it holds no per-user state today); a store of push subscriptions and each one's followed teams (KV or D1, keyed by the subscription endpoint); VAPID keys as Worker secrets and Web Push encryption (RFC 8291) to send; `PushManager.subscribe` in Settings; and a `push` handler in sw.js calling `showNotification` with the same tags. On iPhone and iPad it also needs the app added to the Home Screen.
- **The installed app** (`public/manifest.webmanifest`): standalone, Schedule and Settings shortcuts, icons rendered from the Mac's icon algorithm by `scripts/make-icons.mjs` (192 and 512 with the macOS squircle for installed windows and the Dock; a full-bleed 512 maskable; a full-bleed 180 apple-touch-icon, since iOS rounds corners itself and turns transparency black). The light and dark `theme-color`s match the page and follow Settings → Appearance (`useApplyTheme`).
- **Offline shell** (`public/sw.js`, registered in production only): pages are network first, falling back to the last good `index.html`, so the app opens offline and says it can't connect; `/assets/` (hashed) and the icons are cache first, the shell's own assets fetched on install, 80 kept. `/api/` is never touched: scores always come from the network.

## Accessibility

- **Landmarks:** `aside` for the scores and `main` for the page; beside the sidebar, "Skip to Page" jumps to `main`.
- **Headings:** `h1` per page. On a game, the hero's `h1` is the game in words.
- **Sections** are disclosure buttons inside `h2`s, with `aria-expanded` and a spoken preview when collapsed.
- **Rows and tiles** are links labeled with the game in words: "Liverpool 3, Brighton 1, 67th minute", then "In the tab" when pinned, follows, the situation and the caption, built by `spokenSummary`. Their menu is reachable with Shift-F10 or the Menu key; the hover "…" is out of the tab order (one stop per game).
- **Controls:** segmented controls are radio groups and switches use `role="switch"`.
- **Live regions:** game pages only, never the list (Announcer's policy): one shared polite region (`features/game/core/announce.ts`) for scores, the final whistle and moments. The list's "Updated…" footer and live count are plain text; a chip's `label` is visually hidden text, not a status.
- **Groups, not images, around controls:** a chart that holds links or buttons (At the Plate's names, This At-Bat's pitches, a form strip's games) is a labeled `role="group"`; `role="img"` hides its children from screen readers. A pinnable row inside a list keeps its `<li>` and puts the button inside it.
- **axe:** `qa.spec.ts` runs axe (WCAG 2.1 A and AA plus best practice) over every page type in both schemes at 390 and 1440; it must stay at zero. `label-content-name-mismatch` is off: rows are labeled with the game in words on purpose.
- **Focus** rings show for keyboard users only (`:focus-visible`).
- **Contrast** is tested, and Increase Contrast and Reduce Transparency are honored.
- **Touch:** coarse pointers get a 15px root, so rows reach about 44px, and inputs are at least 16px so phones don't zoom.

## Performance

- **First paint:** the scores list is the only eager route. The initial JS is about 170 KB gzipped: React 68, the router 30, Query 11, and the app with motion's core. motion's layout features (about 32 KB) load after paint. Libraries sit in their own chunks for long-term caching, and hashed bundles are cached for a year (`public/_headers`); the `query` chunk is the query client only, so the persister (`state/persist.ts`) loads with the first page that keeps data on disk. Measured with the persister, the retry policy, the sounds and the shapes in (October 2026): the initial JS unchanged (185.9 KB by gzip -9, +41 bytes) and the scores' first contentful paint the same within noise (median 196 ms against 180 ms over ten runs each, on a busy machine at background priority).
- **Game pages** are split by sport (`features/game/sportPages.ts`): beyond the shell, a page adds about 63 KB gzipped (MLB, plus its 23 KB theater when a play runs), 72 (NFL, soccer) or 90 (NBA), where every sport used to add 113. The shell links games through `data/gameHref.ts`, so the game data layer stays out of the first paint. Keep both seams: `test/unit/bundleSplit.test.ts` fails on a static import across them.
- **Measured** (production build, headless Chromium on the M2, October 2026): scores FCP about 0.1 s with no long tasks; a full load's main thread 250 to 480 ms (team page the most, one 58 ms task); scroll at 60 fps with no frame over 17 ms on the longest pages (a team page, an NBA game; an MLB game and the scores also at 4× CPU throttling); a live demo's heap flat at about 26.5 MB over eight minutes with DOM nodes, listeners, observers and canvases constant; a hidden tab makes no requests.
- **Rendering:** rows and tiles are memoized on their game, and unchanged games keep their identity across polls. Derived lists are recomputed only on a data, settings or minute change.
- **Motion cost:** live dots are compositor-only CSS. Layout animation is turned on only during a toggle, and crest links exist only for the section being toggled; each costs a measurement.
- **No layout thrash:** text is measured with a shared canvas (`features/scores/measure.ts`, RecordFit), widths come from one ResizeObserver per board, and arrow keys read geometry only on a key press.
- **The play theaters** draw on one canvas each, with a frame loop only while something moves and is seen; see [Play theaters](#game-pages) for the measured frame times. On the theater engine (while the page broadcasts) the loop runs only through the plan's moving tiers, one timer wakes it for the next, and each plan is made in 6 ms slices between frames (`PLAN_SLICE_MS`), so no plan is a long task; the numbers are in [the engine's paragraph](#game-pages).
- **Live odds** cost nothing until a game page's Win Probability is on screen, and track one market at a time. Measured (October 2026, M2, Chromium, `/dev/odds` and a real final; the machine busy with other agents' builds): a live game with a quiet market made no animation frames and no requests in 10 s (66 ms of main thread, most of it the harness re-reading its recorded game every 2 s); a busy one (a new price every 2 s, each gliding) 62 frames in 10 s at p50 0.20 ms, p95 0.30 ms, max 1.6 ms of script each; a final, once drawn, 0 frames and 8 ms in 10 s. A hidden tab closes the socket at once; leaving the page closes it and nothing runs in the 20 s after. Finding a market costs two requests (about 10 KB) for the first game of a league's day, one (2 KB) after. The game core carries the matching and the feed (about 9 KB gzipped); the chart is its own chunk (`core/odds/OddsSection.tsx`, 10.7 KB gzipped and 3 KB of CSS), fetched as the page starts looking for the market.
- **Logos** are CDN-resized to 40/64/96/160px buckets, lazy-loaded and decoded asynchronously.
- **The shell's share of the first paint** is about 7.6 KB gzipped (the strips' moments and the CS2 race, the context menu host, the pin, scroll memory and commands). What it can defer, it does: the game menu's items and the team-page helpers (`GameMenuContent`), CS2's live rounds (`csLive.ts`, only while a match is live), the tab score and alerts (`LiveServices`), and the schedule code behind My Teams' fallback and the footnotes' next game days (imported inside their query functions).

## Conventions

- **Names:** Swift names wherever a thing is ported (`stepsBack`, `mergePoll` for ScoreStore.refresh's merge, `planTiles` for TilePlanner.plan, `teamTone`), and Swift field names in models. Components are PascalCase files with a CSS module beside them (`EventRow.tsx` and `EventRow.module.css`). Hooks start with `use`. CSS module classes are camelCase.
- **Comments:** every module and component starts with a short comment saying what it is and why, citing the Swift file it ports. Keep the Swift comments that explain a decision next to the line they explain.
- **Copy:** the Mac's words exactly: "Can't Load Scores", "No games today or tomorrow: …", "Starting soon", "Time TBA". Use Title Case for buttons and labels, sentence case for messages, and en dashes for scores and records ("3–1", "7–1").
- **No component kit:** build from the design system. Add tokens rather than raw colors and lengths.
- **Imports:** extensionless within `src`. `shared/` is imported by both sides and must stay free of DOM and Workers types.
- **Errors:** a failed load shows `ErrorState` at its first failure and retries behind it (`retrying()`, `loadState`; see [State](#state-settings-and-live-scores)); data whose refresh failed stays with a `StaleNote`. A section that fails inside a working page shows `ErrorCopy.inline` ("Trying again shortly", which it does). Polls retry on their own, so their errors stay quiet.
- **Never** link unofficial streams, add a CS2 tier option (S-tier only, one constant), or proxy images.
